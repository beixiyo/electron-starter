# 早期录音事故与演进

本文件是历史记录，不是当前行为说明。当前实现以代码和 [系统结构](./architecture.md) 为准

## 事故主题

### 录音失败后主文件被误判成功

早期路径把 writer 的局部成功或非零文件大小当成可播证据，遇到缺失 moov 或中途解码失败时会产生短文件。后来改为关闭后读取真实媒体时长、核对 reader/writer 状态，并保留 checkpoint/sidecar

### 麦克风和系统音频时间轴错位

热挂 mic、设备切换和 AAC PTS 压缩会让后到的声音被错误挪到开头。sidecar 和逻辑时间线由此成为稳定边界；混音前按有效片段恢复时间位置

### VPIO 让“有 AEC”变成不可控副作用

VPIO 的设备布局、参考流、host time 和资源释放问题多次造成短文件、静音或设备争用。结论不是“不要回声消除”，而是把采集与 AEC 解耦，用显式 reference + AEC3 处理队列替代隐式 Voice Processing 路线

### stop 后整场重处理过慢

离线 AEC 让停止耗时与录音长度成正比，长会议会撞 handoff watchdog。当前目标是录音期间实时处理，停止只做排空、校验和原子提交

## 设计原则的形成

1. 先保护 raw 和正式录音，再尝试增强 clean
2. callback 只采集，不等待下游
3. 任何静默失败都必须有首帧、帧数、时长和错误证据
4. 录音来源、目标 PID、处理器和回退原因都要能从日志恢复
5. 不为未发布格式保留兼容层；版本变更应明确失败
