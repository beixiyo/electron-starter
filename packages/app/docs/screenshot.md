# 区域截图会话

截图只向一个确定的窗口交付结果，不广播图片。`captureId` 隔离同窗口的主动申请者，`fallbackRole` 区分主进程发起截图时的消费角色。

## 渲染端主动申请

使用 `useScreenshotSession(onCaptured)`，默认交付 PNG Blob。Hook 自动核对申请返回的 `captureId`；调用方负责预览 Object URL 的释放。Web 环境下 `available` 为 false。

## 主进程发起

应用装配层通过 `setScreenshotTargetResolver` 注入同步裁决函数，返回具体 `webContents` 和可选 `fallbackRole`。随后可从自己的菜单或快捷键调用 `startCapture()`。模板不预设角色、目标选择策略或额外系统快捷键。

裁决在启动截图、权限检查和原生抓屏之前运行一次；完成和取消沿用这个具体目标。期间焦点改变不重选目标；目标销毁后丢弃事件，也不会投递给同类型的新窗口。显式传入 `owner` 的渲染端申请优先，跳过裁决函数。

接收窗口可使用 `useScreenshotSession(onCaptured, { fallbackRole: 'preview' })`。角色由应用自行命名，同一个窗口只允许一个已挂载的 Hook 注册同一角色，重复注册会明确报错。宿主失效时应卸载订阅，缓存页面应在活动的上层管理订阅。未声明角色的普通申请者不会消费兜底事件。

新会话会取消旧会话；异步抓屏结果仍须通过当前会话身份校验。无裁决函数或裁决无目标时保持原有无投递行为；调用方应在启动前确保接收宿主已就绪。

选区窗口的确认、保存和取消指令必须携带初始化时取得的 `captureId`。主进程同时核对当前会话和发起指令的覆盖层窗口；迟到的旧指令不会关闭新选区、覆盖剪贴板或取用新一轮图片。
